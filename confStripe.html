Guía paso a paso · primera vez

Configurar Stripe para Clarvo, de cero

7 pasos, en orden. No necesitas crear productos ni precios a mano en el dashboard de Stripe — eso lo va a hacer el código automáticamente vía API cuando el onboarding esté construido. Aquí solo dejamos la cuenta lista y las 3 llaves que ese código va a necesitar.

En esta guía

  1. Crear la cuenta de Stripe
  2. Activar la cuenta para cobros reales (modo Live)
  3. Entender modo Prueba vs. modo Live
  4. Obtener las API keys
  5. Configurar el webhook
  6. Dónde van estas 3 llaves en Clarvo
  7. Probar antes de cobrar de verdad
1

Crear la cuenta de Stripe

Entra a stripe.com y crea una cuenta con el correo del negocio (no uno personal — vas a necesitar invitar a más gente del equipo después).

  • Correo + contraseña, o entra con tu cuenta de Google.
  • Nombre del negocio: Clarvo (o la razón social real de ADDV).
  • País: México — esto define impuestos, moneda default (MXN) y qué métodos de pago están disponibles (tarjeta, SPEI, etc.).

Al terminar este paso ya puedes trabajar en modo Prueba — no necesitas activar cobros reales todavía para empezar a construir.

2

Activar la cuenta para cobros reales

Esto es aparte de crear la cuenta — mientras no lo hagas, Stripe te deja construir y probar todo, pero no te deja mover dinero real. Hazlo cuando estés por lanzar, no tiene que ser hoy.

Dashboard → banner superior "Activa tu cuenta", o Settings → Account details

Te va a pedir:

  • Datos fiscales del negocio (RFC, razón social, domicilio).
  • Identidad de quien representa el negocio (identificación oficial).
  • Cuenta bancaria CLABE — aquí es donde Stripe deposita lo cobrado (los payouts), normalmente cada 1-2 días hábiles por default.
La verificación de identidad puede tardar de minutos a un par de días. No lo dejes para el último momento antes de lanzar.
3

Modo Prueba vs. modo Live — el interruptor más importante

Arriba a la derecha del dashboard hay un switch que dice "Test mode". Es LA cosa que más confunde a quien usa Stripe por primera vez, así que quede claro:

Modo Prueba (Test)Dinero falso. Tarjetas de prueba (4242 4242 4242 4242). Sus propias API keys, empiezan con pk_test_/sk_test_. Úsalo para TODO el desarrollo.
Modo LiveDinero real. Tarjetas reales. Keys distintas, empiezan con pk_live_/sk_live_. Solo se usa cuando el onboarding real ya está probado.
Nunca mezcles las keys — un sk_live_ en el .env de desarrollo puede cobrarle de verdad a alguien por accidente al probar. Los productos/precios que se creen por API también son independientes entre Test y Live: todo lo que se pruebe en Test hay que volver a crearlo (automáticamente, vía el mismo código) una vez en Live.
4

Obtener las API keys

Con el switch en Test mode (para empezar):

Dashboard → Developers (menú lateral) → API keys

Vas a ver 2 llaves:

Publishable keypk_test_... — no es secreta, va en el frontend (la página que cobra).
Secret keysk_test_... — SÍ es secreta, solo vive en el backend/control. Clic en "Reveal" para verla.
La secret key nunca va en el código del repo, nunca en un commit, nunca en el frontend. Mismo criterio que ya usa este proyecto para todo secreto: vive solo en el .env del servidor.

Repite este paso cuando actives Live — son llaves completamente distintas.

5

Configurar el webhook

Stripe te avisa de eventos (pago exitoso, pago fallido, suscripción cancelada) mandando una petición HTTP a una URL tuya — eso es el webhook. Es lo que va a permitir que Clarvo sepa cuándo suspender un tenant por falta de pago, automáticamente.

Dashboard → Developers → Webhooks → Add endpoint

Vas a necesitar una URL pública (no localhost) — algo como https://control.clarvo.mx/api/control/stripe/webhook (la ruta exacta la define el código cuando se construya). Selecciona al menos estos eventos:

invoice.payment_succeeded invoice.payment_failed customer.subscription.updated customer.subscription.deleted checkout.session.completed

Al crear el endpoint, Stripe te da un Signing secret (whsec_...) — esa es la tercera llave. Sirve para confirmar que el webhook de verdad viene de Stripe y no de alguien haciéndose pasar por Stripe.

En desarrollo local (sin URL pública) se usa el Stripe CLI (stripe listen --forward-to localhost:4001/...) — te da un signing secret de prueba distinto, válido solo mientras el comando corre. Lo instalamos cuando el código del webhook ya exista.
6

Dónde van estas 3 llaves en Clarvo

Mismo patrón que ya usa todo el proyecto para secretos de infraestructura (nunca en la BD, nunca en el código) — van al .env del servidor, y Claude las agregará a docker-compose.yml cuando construya la integración:

STRIPE_SECRET_KEY=sk_test_... STRIPE_PUBLISHABLE_KEY=pk_test_... STRIPE_WEBHOOK_SECRET=whsec_...

Las 3 son de Test mode mientras se construye y se prueba. El día que se pase a Live, se reemplazan por las 3 equivalentes de Live (nunca se mezclan).

7

Probar antes de cobrar de verdad

Con las keys de Test puestas, Stripe tiene tarjetas de prueba que simulan distintos resultados — útiles para probar el onboarding completo, incluido el camino de "el pago falló":

Pago exitoso4242 4242 4242 4242
Pago rechazado4000 0000 0000 0002
Fondos insuficientes4000 0000 0000 9995
Requiere autenticación (3D Secure)4000 0025 0000 3155

CVC y fecha de expiración: cualquier valor futuro/cualquier número de 3 dígitos funciona en modo Test.

Con esto ya puedes probar el onboarding completo (pago exitoso, pago fallido con el borrador que pidió guardarse, reintentos) sin arriesgar un centavo real ni necesitar la cuenta activada todavía.

Qué sigue

Con la cuenta creada (paso 1-2 pueden ir en paralelo con el desarrollo) y las 3 llaves de Test en la mano, ya podemos construir: creación de Producto/Price por API, el checkout del onboarding, el webhook que escucha los eventos, y la pantalla de configuración de reintentos/mensajes en /control. Avísame cuando tengas las keys de Test listas y seguimos con el refinamiento del onboarding.
