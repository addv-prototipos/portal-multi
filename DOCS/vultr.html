2 Por qué este armado

  • ✔4 vCPU / 8GB alcanza para los 5 contenedores del stack corriendo juntos: backend, control, frontend (nginx), mysql, garage.
  • ✔Datos (MySQL datadir + bucket Garage) viven en el Block Storage desde el día uno — nunca en el disco del compute.
  • ✔Cuando el bloque se llena: resize desde el dashboard + resize2fs adentro del servidor. Cero downtime, cero migración de datos.
  • ✔Si el día de mañana falta RAM/CPU: se sube el plan del compute (requiere apagar/prender la instancia — downtime corto, minutos). El disco de datos no se toca en ese proceso.

3 Paso a paso — crear el Compute

  1. Dashboard Vultr → Compute → Create Instance.
  2. Tipo de plan: Dedicated CPU o Shared CPU según disponibilidad/precio del momento — filtrar en el buscador de planes por 4c-8g (4 vCPU, 8GB).
  3. Elegir la fila cuyo Storage diga Block Storage (boot separado del disco físico) en vez de "Local NVMe" — así el disco de arranque también queda desacoplado, no solo los datos.
  4. Región: la más cercana a México disponible en esa familia de plan (Ciudad de México si aparece listada; si no, la más cercana en AMER — confirmar en el selector de Location).
  5. Sistema operativo: Ubuntu LTS más reciente disponible (es lo que ya usa prod/README-DESPLIEGUE.md del proyecto).
  6. SSH Key: subir/generar una antes de desplegar — nunca dejar solo password.
  7. Hostname/etiqueta: algo identificable, ej. clarvo-prod-01.
  8. Revisar el resumen de costo a la derecha ($/hr × 672 = costo mensual real) antes de confirmar.
  9. Deploy Now — esto SÍ cobra, confirmar antes de dar clic final.

4 Paso a paso — agregar el Block Storage

  1. Dashboard → Storage → Add Block Storage.
  2. Tamaño inicial: 100 GB, tipo NVMe.
  3. Región: la misma región exacta del compute — si no coincide, no se puede atachar.
  4. Attach: elegir la instancia creada en el paso 3.
  5. Dentro del servidor (SSH), aparece como /dev/vdb. Formatear y montar (ver sección 5).

5 Comandos dentro del servidor (una sola vez)

parted -s /dev/vdb mklabel gpt
parted -s /dev/vdb unit mib mkpart primary 0% 100%
mkfs.ext4 /dev/vdb1
mkdir -p /mnt/data
mount /dev/vdb1 /mnt/data

# persistir en reinicios
blkid /dev/vdb1   # copiar el UUID que imprime
echo "UUID=<uuid-copiado> /mnt/data ext4 defaults 0 2" | sudo tee -a /etc/fstab
Después de montar: editar docker-compose.prod.yml para que los volúmenes de mysql y garage apunten a rutas dentro de /mnt/data en vez del disco raíz — ese es el paso que hace que crecer el bloque después sea realmente "solo asignar espacio".

6 Crecer el almacenamiento después (sin downtime)

  1. Dashboard → Storage → seleccionar el volumen → Resize → nuevo tamaño (ej. 100→250 GB).
  2. Dentro del servidor: resize2fs /dev/vdb1 — toma el nuevo tamaño en caliente.
  3. Nada se detiene, nada se mueve. MySQL/Garage ni se enteran.
