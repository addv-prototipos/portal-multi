1

Antes de empezar

Estas tarjetas solo funcionan si la cuenta de Stripe está en modo Prueba (clave sk_test_...) — en modo Live, Stripe las rechaza todas de inmediato porque no son tarjetas reales.

  • Verifica el modo en /control → Upscale y Stripe → Configurar Stripe → Métodos de pago: el badge debe decir "Modo: prueba".
  • El sitio público (clarvo-Site) debe estar corriendo y apuntando a tu control local — si ves "No se pudo conectar" al confirmar el plan, es un problema de CORS/CSP, no de la tarjeta.
  • Para TODAS las tarjetas de esta guía: cualquier fecha de vencimiento futura, cualquier CVC de 3 dígitos (4 en Amex), cualquier código postal.
Fecha de vencimiento: cualquier mes/año futuro (ej. 12/30)
CVC: cualquier 3 dígitos (ej. 123)
Código postal: cualquiera (ej. 00000)
Nombre en la tarjeta: cualquiera
Nunca metas una tarjeta real aquí, ni siquiera "para ver qué pasa" — en modo Live estos números solo generan un rechazo real y no prueban nada.

Tarjetas con autenticación (3D Secure)

En México muchas tarjetas piden un paso extra de autenticación del banco (3D Secure / "verificado por Visa"). Stripe simula esa pantalla en modo prueba — estas tarjetas la disparan a propósito.

NúmeroQué pasaResultado

4000 0000 0000 3220Pide autenticación — clic en "Fail authentication" en esa misma pantallaFalla la autenticación

Útil para confirmar que el checkout de Clarvo no se rompe si el banco pide este paso extra (pasa seguido con tarjetas mexicanas reales).

5

OXXO y SPEI (pago diferido)

No llevan número de tarjeta — Stripe genera una ficha/referencia y el borrador se queda en provisioning (no activa el tenant) hasta que el pago se confirma de verdad. Así se ven en el checkout de prueba:

  • OXXO: Stripe muestra un voucher de prueba con código de barras — no existe una tienda real donde "pagarlo".
  • SPEI: Stripe muestra una CLABE de prueba para "transferir" — tampoco hay banco real del otro lado.

Para simular que el cliente SÍ pagó en la tienda/banco (y disparar el webhook real checkout.session.async_payment_succeeded), dos formas, de más fácil a más técnica:

  1. Dashboard de Stripe (recomendado): Payments → busca el Payment Intent con estado "Requires action"/"Processing" → botón "Mark as succeeded" (test mode marca el voucher como pagado y dispara el webhook real).
  2. Stripe CLI, si ya tienes stripe listen corriendo: stripe trigger checkout.session.async_payment_succeeded (dispara un evento de prueba genérico, útil para probar el handler sin esperar el Dashboard).

Para simular que nunca se pagó (y ver entrar los recordatorios automáticos): simplemente no hagas nada — el borrador se queda pendiente y /control → Recordatorios lo debe mostrar "en seguimiento" (botón "Procesar ahora" para no esperar el scheduler real de 1h).

Paso a paso: pago exitoso completo

  1. En el sitio, elige un plan → "Confirma tu plan" → Continuar.
  2. "Método de pago" → resuelve el Turnstile (en local pasa solo) → "Pagar $X y continuar".
  3. Te redirige a checkout.stripe.com. Usa 4242 4242 4242 4242, fecha/CVC/código postal cualquiera, correo cualquiera.
  4. Clic en Pagar. Stripe redirige de vuelta a Clarvo.
  5. El modal entra a "Paso 5" y empieza a consultar solo (polling cada 5s) si ya se activó — no hace falta recargar nada, en unos segundos debe mostrar el resultado con el usuario/URL del admin (y del portal, si el plan lo incluye).
Si en ~10-15s no cambia, el webhook no llegó — revisa Cómo confirmar qué pasó de verdad.
7

Paso a paso: tarjeta rechazada

  1. Repite los pasos 1-3 de arriba, pero usa 4000 0000 0000 0002 (rechazo genérico).
  2. Stripe muestra el error EN su propia página ("Your card was declined") — Clarvo todavía no se entera de nada.
  3. Para completar la prueba de "sí falló": en vez de reintentar, cierra la pestaña o da clic en la flecha de "volver" de Stripe.
  4. De vuelta en el sitio, el borrador sigue en pendiente (no "fallido" — ese estado es para OXXO/SPEI que expiran, ver sección 5). Puedes volver a intentar el pago completo desde el mismo link/token.
8

Paso a paso: OXXO (pendiente → recordatorio → pago)

  1. En "Método de pago", si el Dashboard de Stripe tiene OXXO activado, elige esa opción al llegar al Checkout (si no la ves, actívala primero — ver DOCS/confStripe.html, paso 8).
  2. Stripe muestra el voucher de prueba. Cierra esa pestaña sin "pagarlo" — el borrador queda provisioning.
  3. En /control → Recordatorios, busca el borrador — debe aparecer "en seguimiento" con "Próximo intento: Pronto". Clic en "Procesar ahora" para forzar el envío sin esperar.
  4. Para simular que SÍ pagó: Dashboard de Stripe → el Payment Intent de esa sesión → "Mark as succeeded". El webhook real activa el tenant.
9

Cómo confirmar qué pasó de verdad

Nunca confíes solo en lo que muestra el modal del sitio — confirma contra el estado real:

  • /control → Empresas: busca por el slug o nombre que capturaste — estado debe pasar de "Provisionando" a "Activo".
  • Dashboard de Stripe → Developers → Webhooks → tu endpoint → pestaña "Events" — confirma que el evento llegó con 200 (no 4xx/5xx).
  • Si tienes stripe listen corriendo en la terminal, ahí se ve cada evento y su respuesta en tiempo real — el primer lugar a mirar si algo no activa.
10

Limpiar después de probar

Cada prueba completa crea un tenant real en tu base local. Si no lo vas a seguir usando:

  • /control → Empresas → "Dar de baja" (reversible) o, desde Papelera, "Eliminar definitivo" (borra la base de datos del tenant, irreversible).
  • Los pagos de prueba en Stripe no cuestan nada ni hay que "reembolsarlos" — pero puedes borrarlos del Dashboard (Payments → ⋯ → Delete) si quieres la lista limpia.

Fuente de estos números

Son las tarjetas de prueba oficiales y públicas de Stripe (stripe.com/docs/testing) — no son datos sensibles, cualquiera con una cuenta de Stripe las puede usar en modo prueba. Si Stripe agrega/cambia alguna en el futuro, esa página es la fuente de verdad, no esta guía.
